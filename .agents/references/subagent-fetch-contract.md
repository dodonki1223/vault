# fetch 系サブエージェントの共通契約

## 目的

複数の fetch 系 skill をサブエージェントとして並列実行するときに、入力と出力の形を揃えるための共通契約。

この reference は model 指定のルールではない。model の選択、固定、切り替え方法は別の運用ルールまたは agent 設定で扱う。

## この契約を使う場面

- Slack、Linear、Notion、GitHub、Google Meet、Google Sheets など、複数の情報源から並列に情報を取得するとき。
- `workflow-fetch-and-classify-materials` のような orchestration 役が、fetch 系 skill の返答を機械的に統合したいとき。
- 情報源ごとに返し方がばらついて、後続の classify や統合処理が重くなるのを防ぎたいとき。

## この契約の対象

- 対象: read-only の fetch 系 skill、または同等の read-only サブエージェント。
- 非対象: classify、review、write、Project 更新、Linear 更新、Slack 送信などの後続処理。

## 前提

- fetch 系サブエージェントは取得だけを担当する。
- 優先度判断、通知要否判断、更新先への反映、次アクションの新規作成は行わない。
- source に明示されていない推測や補完はしない。
- 認証不足、権限不足、対象不明のときは、無理に別手段へ広げず、失敗理由を返す。

## 入力契約

呼び出し側は、できるだけ次を明示して渡す。

- 情報源:
  - Slack / Linear / Notion / GitHub / Google Meet / Google Sheets / その他
- 対象:
  - channel、thread URL、issue ID、Project URL、document URL、sheet 名、meeting title など
- 期間:
  - 絶対日付で指定する。未指定なら、むやみに広げない
- 観点:
  - 何を見たいか。例: 依頼、決定事項、ブロッカー、期限変更、担当変更、レビュー依頼
- 除外:
  - 何を拾わないか。例: bot 通知、雑談、完了済みの古い更新、対象外 issue
- 呼び出し理由:
  - なぜ取得するのか。例: status 更新前の材料集め、単発調査、意思決定確認
- 任意の短い文脈:
  - Project 名、note 名、調べたいテーマ、関係者など

### 入力が不足している場合

- 安全に推測できる最小範囲だけで取得する。
- 対象または期間を安全に絞れない場合だけ、短い質問を 1 つする。
- 取得できないまま広げるのではなく、`取得できなかった理由` を返す。

## 出力契約

fetch 系サブエージェントは、成功時も失敗時も、次の骨格を維持して返す。

```markdown
## <情報源> 情報

### 取得範囲

- 対象:
- 期間:
- 観点:
- 除外:

### 取得結果

| 時刻または更新日時 | 情報源 | 主体 | 情報 | リンク | 取得理由 |
|---|---|---|---|---|---|
| YYYY-MM-DD HH:mm JST | channel / issue / page / sheet / meeting など | 発言者 / 担当者 / 更新主体 | source に基づく短い要約 | [表示名](URL) | 観点との関係 |

### 不足している可能性

- 
```

## 列の意味

- `時刻または更新日時`:
  - source から分かる時刻。日付しか分からない場合は日付だけでもよい。
- `情報源`:
  - channel 名、issue ID、document 名、sheet 名、meeting 名など、読み返して識別できる単位。
- `主体`:
  - 発言者、担当者、更新者、会議参加者など、その情報の主体。
- `情報`:
  - source に忠実な短い要約。長文引用は避ける。
- `リンク`:
  - 必ず表示名付きにする。URL 単独では置かない。
- `取得理由`:
  - その行を残した理由。観点との関係を短く書く。

## 失敗時の出力契約

取得できなかった場合は、通常の `取得結果` の代わりに次を返す。

```markdown
## <情報源> 情報

### 取得範囲

- 対象:
- 期間:
- 観点:
- 除外:

### 取得できなかった理由

- 種別: tool 未検出 / 認証不足 / 権限不足 / 対象不明 / 該当なし / その他
- 確認したこと:
- 次にユーザーが行うこと:
- 再試行条件:

### 不足している可能性

- 
```

## 取得結果に含めるもの

- 指定された観点に直接関係する事実。
- 後続で再確認する価値がある source link。
- ユーザーや関係者の pending ask、レビュー依頼、期限変更、担当変更、決定事項の痕跡。
- status 更新や単発調査で判断材料になりそうな短い差分。

## 取得結果に含めないもの

- ログ全文、コメント全文、議事録全文。
- 指定観点と関係ない定型通知。
- ただ URL が並んでいるだけのもの。
- source にない推測、優先度判断、結論。
- 後続 workflow が比較すべき `変更点` の新規作成。

## classify との境界

fetch 系サブエージェントは、次を行わない。

- `事実`、`決定事項`、`推測`、`未解決事項`、`次アクション` への分類
- 情報源横断での重みづけ
- 矛盾解消
- Project、note、Linear、Slack への反映

これらは `classify-fetched-materials` またはメイン agent 側で扱う。

## model との関係

この契約は、どの model を使うかは定義しない。

- Claude でサブエージェントに model を直接指定する運用
- Codex で session や agent 設定で model を切り替える運用

のどちらでも使えるように、入出力だけを固定する。

## 最低限の期待値

良い fetch 系サブエージェントは、次を満たす。

- 狭く取得する。
- 取得範囲を明示する。
- source に忠実な短い要約で返す。
- 失敗時に、次に必要なことが分かる。
- 後続の classify がそのまま受け取れる。
