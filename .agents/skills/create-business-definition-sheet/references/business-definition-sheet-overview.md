# 業務定義シートとは

出典: 『業務設計の教科書』WORKING 1「業務定義シートを作成」

## なぜ業務定義シートが必要なのか

業務改善というと、まず「やり方」を変えることに意識が向きがちだが、本来最初に取り組むべきことは「何のためにやっているのか」「何が成果物か」といった内容をあらためて言語化し、関係者と共有することである。

この段階で新たな目的や成果物を設定するわけではなく、もともと存在していた意図や基準を明確にして、関係者全体で認識をそろえることが大切になる。業務定義シートは、この「現状の業務の構造を把握し、見える化の足がかりとなるツール」にあたる。

## 業務設計全体における位置づけ

業務設計は、いきなり細かいフローを描き始めるのではなく、まず業務の全体像を捉えることから始まる。業務定義シートは、業務ごとの基本情報を A4 1 枚にまとめたものであり、このシートを作ることで、この後に実施する「業務の地図」の作成や詳細な設計を行う際の土台を整えることができる。

このシートが対象にするのは業務全体であり、個別の工程ごとの詳細な業務定義は次のステップ(業務の地図の作成、個別工程の詳細設計)で行う。ここではまず全体を俯瞰して業務の輪郭をつかむことを目的とする。

## 業務定義シートの観点(表 W1.1)

| 項目 | 内容の説明 |
|---|---|
| トリガー | 業務が始まるきっかけは何か |
| 目的 | 何のためにその業務をやっているのか |
| INPUT | どんな情報や資料をもとに処理を行っているか |
| DO | どんな処理をしているのか |
| OUTPUT | 処理の完了とはどういう状態か、何が成果物か |

これらの項目を丁寧に言語化することで、業務の目的と手段がずれていないかを確認しつつ、関係者の認識を揃えるための議論のたたき台を提示できる。

## 業務定義シートの整理項目(表 W1.2)

実際の業務定義シートでは、上記の観点に加えて次の項目も整理する。

| 項目 | 内容 |
|---|---|
| 業務名 | この業務の名称を記載する |
| 担当者・関係者 | 業務に関わる人を記載する。主担当だけでなく関係者も含める |
| トリガー | 業務が始まるきっかけ(例: 月初、依頼の受領など)を明確にする |
| 所要時間 | 処理にかかる平均的な時間を記載する |
| 発生頻度 | 業務がどのくらいの頻度で発生するかを記載する |
| 目的 | この業務がなぜ存在するのか、何を達成するためのものかを書く |
| INPUT | 業務に必要な情報や資料を具体的に列挙する |
| DO | 処理の内容を簡潔に書き出す。詳細化は後のステップで行う |
| OUTPUT | 「完了」と見なす状態と、その際に得られる成果物を明確にする |

## シートのレイアウト(図 W1.1)

```text
業務定義シート | 業務名: ______________________

担当者・関係者     | トリガー          | 所要時間 | 目的
・                 |                  |         |
・                 | 発生頻度          |         |
・                 | 毎日・週次・月次・その他(   ) |  |

INPUT              | DO                | OUTPUT
・                 | ・                | <完了とみなす状態>
・                 | ・                |
                    |                   | <成果物>
```

## 目的と OUTPUT の違いについて

目的と OUTPUT は似ているようでいて、実は役割が異なる。

- **目的**: 「なぜその業務をやっているのか」という背景や存在理由を示すもの。業務の上位概念にあたる。
- **OUTPUT**: 「この業務が終わったとみなせる状態は何か」という完了条件と成果物を定義するもの。

たとえば「請求書の発行」の目的は「正確な金額を顧客に伝え、スムーズな入金を実現すること」である。しかし OUTPUT は「顧客に請求書を送付し、必要な記録が残っていること」といった形で、業務の終わりを具体的に示す。

このように目的と OUTPUT を分けて記述することで、「何のためにやっているのか」と「終わったかどうかをどう判断するか」が混同されるのを防ぎ、業務の質を高めることができる。業務を改善・自動化・委託などする際にも、この 2 つの視点が分かれていることが重要になる。

## 書き方のポイント

- 実際の業務の流れを頭の中でシミュレーションしながら書く。
- 目的や OUTPUT を明確にして、ムダな処理や曖昧な仕事を見つける。
- 自分で埋められないところがある場合、関係者にヒアリングする。
- まずは 1 人で作ってみるのがオススメ。目的や DO、OUTPUT などは人によって内容が若干違うこともあるため、可能であれば各自で業務定義シートを作成した上で集まり、内容のすり合わせを行うとスムーズ。
- 記入例はあくまで今後のディスカッションや作業のたたき台であり、あまり悩まず時間をかけすぎずに作成することがポイント。

## 記入例: 請求書発行業務の業務定義シート(図 W1.2)

| 担当者・関係者 | トリガー | 所要時間 | 目的 |
|---|---|---|---|
| ・営業アシスタント<br>・営業担当者<br>・経理担当者 | 月初または納品完了時 | 3 日 | 取引先に正確な金額を伝え、スムーズな入金を実現するため |

発生頻度: 週次(その他: 納品時)

| INPUT | DO | OUTPUT |
|---|---|---|
| ・受注データ<br>・納品書<br>・取引条件<br>・顧客情報 | ・請求金額の確認<br>・請求書の作成<br>・請求書のチェック<br>・顧客へのメール送付 | **完了とみなす状態**<br>全ての顧客の請求書が送付されている<br><br>**成果物**<br>請求書、メール |
