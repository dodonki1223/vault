# Project リスク判定 skill

## 背景

Project note、Linear Project、milestone、issue、関連ドキュメント、MTG メモなどを入力として受け取り、標準リスクモデルを参考に Project のリスクを構造的に判定する skill を検討する。

参考:

- [プロジェクトを円滑に進めたいならタスクではなくリスクを見よ！ - Qiita](https://qiita.com/dodonki1223/items/48b09a93ff9ee37003f9#%E6%A8%99%E6%BA%96%E3%83%AA%E3%82%B9%E3%82%AF%E3%83%A2%E3%83%87%E3%83%AB%E3%81%8C%E7%A4%BA%E3%81%99%E6%A7%8B%E9%80%A0%E3%81%A8%E3%81%97%E3%81%A6%E3%81%AE%E3%83%AA%E3%82%B9%E3%82%AF)

## ほしい状態

- Project の現在地から、将来起こるかもしれない不確実な事象をリスクとして抽出できる。
- すでに発生している課題や問題と、まだ発生していないリスクを分けられる。
- リスクを単なる一覧ではなく、リスク事象、リスク事象のドライバー、発生確率、影響、影響のドライバー、総損失量の観点で整理できる。
- リスク同士の連鎖、階層、見えづらい前提、認識のばらつき、掛け算的に影響が広がる可能性を見られる。
- 予防できるリスク、緩和できるリスク、備えるしかないリスクに分け、次に確認すべきことを出せる。
- Project 更新時に `status.md` の `ブロッカー` や `未解決事項` とは別に、リスクレビューの結果をユーザーへ短く返せる。

## 出力案

```markdown
## リスク判定

### 重要リスク

- リスク事象:
  - ドライバー:
  - 発生確率:
  - 影響:
  - 影響ドライバー:
  - 総損失量:
  - 対応方針: 予防 / 緩和 / 備え
  - 次に確認すること:

### 課題・問題として扱うもの

-

### 判断に必要な不足情報

-
```

## 最初にやること

- `assess-project-risks` のような read-only skill にする。
- 標準リスクモデルの原則は `.agents/references/project-risk-principles.md` のような reference に分ける。
- Project note 更新 workflow skill から、必要なときだけ呼び出す。
- リスクをすべて `status.md` に書くのではなく、重要なものだけ Project note へ統合し、詳細はユーザーへのレビュー結果として返す。

## 完了条件

- read-only skill として作成されている。
- 重要リスク、課題・問題、不足情報を分けて出せる。
- Project note へ統合すべきものと、レビュー結果に留めるものを分けられる。
