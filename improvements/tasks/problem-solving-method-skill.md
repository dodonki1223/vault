# 問題解決メソッド skill

## 背景

問題を「理想と現実のギャップ」として捉え、共通言語で議論するためのフレームワークがある。個人の責任追及ではなくチームでの共同解決を目指す場面や、議論が平行線になり認識ズレが起きている場面で使うと、事実と解釈を分離したうえで真因と次の行動に落とし込める。

参考:

- [問題解決メソッド - サイボウズ式Teamwork blog](https://teamwork.cybozu.co.jp/blog/problem-solving-method.html)

## ほしい状態

- 問題（理想と現実のギャップ）を入力として受け取り、以下の5ステップで整理できる。
  1. 問題のタイトル化: 問題を一言で言い表す。
  2. マトリックス分析: 理想・現実・事実・解釈の4象限に分類する。特に事実（五感で確認できる共通認識）と解釈（個人的主観）を分離する。
  3. 原因洗い出し: 現実を引き起こした「人の行動」にフォーカスし、自責形式（「私は○○していない」）で "なぜ" を繰り返し真因に到達する。
  4. 課題列挙: 現実を理想に近づけるための具体的行動を、「誰が何をするか」の形で抽出する。
  5. 優先度付け: 影響範囲・コスト・リスクで実行可能性を評価する。
- 5ステップ全部だけでなく、事実と解釈の分離のみなど部分的な活用もできる。
- read-only skill として、判断結果をユーザーへ提示し、後続の対応（Linear issue 化、Project note への反映など）は別 skill / 別依頼に委ねる。

## 最初にやること

- `assess-project-risks`（将来の不確実な事象＝リスクを扱う）、`decompose-task-from-materials`（完了条件から作業タスクへの分解）とは目的が異なることを踏まえ、責務の境界を明確にする。
- 5ステップの出力 format を検討する（例: タイトル、マトリックス、真因、課題一覧、優先度付き課題一覧）。
- どの場面で呼び出すか（Project の停滞、認識ズレ、振り返りなど）を整理する。

## 完了条件

- read-only skill として作成されている。
- 5ステップ全体、または部分適用（事実と解釈の分離のみ等）のどちらでも使える。
- 既存の risk 判定 skill・タスク分解 skill と責務が重複していない。

## 残課題

- 部分適用時の入出力の粒度をどう決めるか。
